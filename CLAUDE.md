# Hive — project context

> Read this before modifying anything. It captures the architecture, the
> conventions, and the design decisions behind the current behaviour. Keep it up
> to date when you change how a system works.

## What this is

A native SwiftUI implementation of the board game **Hive** (surround the enemy
Queen Bee on all six sides). Two pieces:

- **`HiveEngine/`** — a pure Swift Package with all the game logic and **no UI**.
  Value types only; unit-tested with Swift Testing (`swift test`, no simulator).
- **`HiveApp/`** — the iOS app (SwiftUI). The Xcode project is generated by
  **XcodeGen** from `HiveApp/project.yml`.

```
HiveEngine/Sources/HiveEngine/

  Piece.swift         Bug/PlayerColor/Piece  (Bug.displayName, Bug.tileName, Bug.letter)
  Board.swift         stacks, occupancy, One-Hive connectivity  (Codable)
  Rules.swift         sliding freedom, beetle gate, jumps, mosquito copy-ability
  Move.swift          Move / GameResult
  GameState.swift     turn flow, placement/queen rules, win detection  (Codable)
  MoveGenerator.swift legal placements & per-bug moves
  AI.swift            negamax + alpha-beta + heuristic (incl. megaEasy tutorial tier)

HiveApp/Sources/
  HiveApp.swift       @main App
  ContentView.swift   app router (Home vs Game), top bar, overlays
  HomeView.swift      hero home screen with 3D showcase, CTA buttons & online placeholder
  BoardView.swift     zoomable/pannable board, camera controls, auto-fit, drag targets/ghost
  TileView.swift      one hexagon tile (icon above name, tinted in the bug's accent)
  BugIcon.swift       hand-drawn Shape glyph per bug (see "Tile visuals")
  HandTrayView.swift  a player's remaining tiles (dynamically sized, see "Tile visuals")
  DragState.swift     @Observable drag tracking (hand/board to target, ghost position)
  MovementDiagramView.swift animated mini-board loop demonstrating bug movement
  TutorialView.swift  guided tutorial overlay, step script, and per-bug movement drills
  ColorDrawOverlay.swift 3D coin-flip / tile-spin animation for random side assignment
  NewGameSheet.swift  GameMenuSheet (setup / menu, incl. Play Tutorial) + RulesView (pushed)
  OnboardingView.swift first-launch tutorial overlay + OnboardingState flag
  GameController.swift @Observable @MainActor owner of state, AI, persistence, drag/drop
  GamePersistence.swift  SavedGame + UserDefaults cache
  Theme.swift         palette (reads asset-catalog colours) + per-bug accent
  Haptics.swift       tactile feedback wrappers
HiveApp/Resources/Assets.xcassets/
  Hive*.colorset      every app colour (see "Colours & assets")
```

## Build / test / run

```bash
# Engine tests (fast, no simulator) — run these for any engine change.
cd HiveEngine && swift test

# App: regenerate the project after adding/removing files, then build.
cd HiveApp && xcodegen generate
xcodebuild -scheme Hive -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro' build

# Seed an illustrative mid-game board (for screenshots):
SIMCTL_CHILD_HIVE_DEMO=1 xcrun simctl launch booted com.hivestudy.Hive
```

Bundle id: `com.hivestudy.Hive`. Deployment target iOS 17.

## Conventions & gotchas

- **XcodeGen owns the project.** Edit `project.yml`, never `Hive.xcodeproj`
  directly; sources are globbed from `Sources/` and `Resources/`, so a new file
  is picked up on the next `xcodegen generate`.
- **The engine stays UI-free and pure.** No SwiftUI/UIKit imports; keep types
  value semantics so the AI can copy states cheaply and the app can snapshot for
  undo/persistence.
- **SourceKit lies about `HiveEngine`.** In-editor diagnostics may say
  `No such module 'HiveEngine'`; that's the indexer not resolving the SPM
  dependency. The real check is `xcodebuild` / `swift test`.
- **Big SwiftUI view expressions time-check slowly.** If the compiler says "unable
  to type-check this expression in reasonable time", split the view into smaller
  sub-expressions / computed properties (see `TileView.emblem` +
  `emblemBackground`).
- `Hex` is a dictionary key in `Board.stacks`; JSON round-trips fine (encoded as
  an array of key/value pairs), which is what persistence relies on.

## Systems

### Tile visuals: icon + name, tinted, no background plaque
`TileView.emblem` shows each tile's own hand-drawn **icon** (`BugIcon`, a
`Shape`-based glyph, one per bug) **above** its actual creature name
(`Bug.tileName`). Both are tinted directly in the bug's `HiveTheme.accent`
colour and sit straight on the plain hexagon — there is **no** separate
coloured plaque/capsule behind them (there used to be; it was removed so the
tile colour itself stays legible). `Bug.letter` still exists in the engine but
the UI never uses it.
- **No SF Symbol animal emblems** — Apple ships accurate symbols for barely any
  of these bugs (no spider, grasshopper, beetle, mosquito, pillbug), so mixing
  a couple of real symbols with custom art reads as inconsistent. All eight
  bugs share one drawn style instead: `BugIcon` dispatches to a private
  `GlyphShape` per bug, each a hand-authored `Path` in `BugIcon.swift`'s
  `BugGlyphs` enum, normalized via `CGRect.pt(x:y:)` (fractions 0...1) so it
  scales with whatever frame it's given. Every glyph is filled with
  **even-odd** fill (`FillStyle(eoFill: true)`) so a shape that lies fully
  inside another (a ladybug's spots, a beetle/ladybug's seam line, a pillbug's
  segment lines) becomes a cut-out showing the tile colour through, instead of
  invisible same-colour-on-same-colour.
- Icon/name colour comes from `.foregroundStyle(HiveTheme.accent(bug, on:
  piece.color))` on the parent `VStack`; `BugIcon`'s shape uses the default
  `fill(style:)` (no explicit colour), which inherits that environment
  foreground style — don't hardcode a colour inside `BugIcon` or this
  inheritance breaks.
- **Accent is tile-colour-aware.** On the cream **white** tiles the Queen's
  bright yellow and the Grasshopper's mid-green wash out, so `accent(_:on:)`
  swaps in darker, higher-contrast variants (`HiveAccentQueenOnWhite`,
  `HiveAccentGrasshopperOnWhite`) *only* when `on: .white`. Every other bug, and
  both bugs on **black** tiles, keeps its vivid signature colour. Callers that
  draw on a dark background (e.g. the game-over crown) omit `on:` to stay vivid.
- Tile colours themselves are unchanged by any of this: black tiles render
  from `HiveBlackTileTop/Bottom` (now genuinely near-black — see "Colours &
  assets"), white tiles from `HiveWhiteTileTop/Bottom` (the cream/tan tone).

### Colours & assets
**Every colour lives in the asset catalog**, not as an RGB literal in code.
`Theme.swift` only names them: `Color("HiveBgTop")`, `Color("HiveAccentQueen")`,
etc. To change the palette, edit the `.colorset`s in
`HiveApp/Resources/Assets.xcassets/` (Xcode's colour editor). Naming scheme:
`HiveBg*`, `HiveWhiteTile*` / `HiveBlackTile*`, `HiveWhiteInk` / `HiveBlackInk`,
`HiveSelection` / `HiveTarget` / `HiveLastMove` / `HiveDanger`, one
`HiveAccent<Bug>` per bug, plus the two white-tile overrides
`HiveAccentQueenOnWhite` / `HiveAccentGrasshopperOnWhite` (see "Tile visuals" →
tile-colour-aware accent). Add a matching `.colorset` if you add a colour.
`HiveBlackTileTop`/`HiveBlackTileBottom` are deliberately near-`(0,0,0)` —
black pieces should read as **actually black**, not the dark navy-gray they
used to be.

### Hand tray: 2-tier spacious layout (no scrolling)
The UI displays only **one** hand tray at the bottom of the screen — the human
player's hand (`game.options.humanColor` in `vsAI` mode, or the active player in
`twoPlayer` mode). The opponent's tiles are hidden, freeing vertical space for the board.
- **Enlarged pieces**: Chips are sized at a generous `chipSize: 34`, making bug
  drawings and text large, crisp, and comfortable to tap or drag.
- **Two-row organization**:
  - **Top row**: Rainha, Aranha, Besouro (`.queen`, `.spider`, `.beetle`).
  - **Bottom row**: Gafanhoto, Formiga, Mosquito, Joaninha (`.grasshopper`, `.ant`, `.mosquito`, `.ladybug`).
- **Zero scroll**: All pieces are visible simultaneously in their rows with no
  scrolling needed. If a row becomes empty as pieces are placed on the board,
  the remaining row centers smoothly.

### Status text: personal & readable
In `vsAI` matches, status badges read **"Sua vez"** / **"Vez do oponente"** (or
**"Computador pensando…"** while the AI calculates), rather than impersonal
"Brancas / Pretas" labels. Win announcements read **"Você venceu! 🎉"** /
**"Oponente venceu"**.

### Random side assignment & 3D color draw animation
When a new match begins (or when clicking "Novo Jogo" / "Jogar Novamente"),
the game randomly determines whether the player gets **White** (moves first) or
**Black** (computer moves first) by default (`GameOptions.ColorChoice.random`):
- **`ColorDrawOverlay`**: A 3D coin-toss / tile-spin animation featuring a large
  hexagonal Queen tile rotating on its Y-axis with realistic physics
  deceleration (`rotation3DEffect`, perspective 0.75).
- Alternates between White (Gold) and Black (Yellow) faces during flight with
  micro-haptic ticks on each half-turn.
- Lands on the assigned color with a dynamic scale bounce, an expanding golden
  shockwave ring, and `Haptics.success()`.
- If Black is drawn, the AI starts calculating its opening move immediately once
  the draw overlay dismisses.

### Hero Home Screen (`HomeView.swift`) & Gyroscope Parallax (`MotionManager.swift`)
The initial app entry point is a dedicated, visually stunning **Home Screen**:
- **3D Hero Showcase**: Centered towards the top, displaying a large 3D
  hexagonal tile with smooth Y/X perspective tilts (`Hero3DShowcase`).
  - Automatically flips every **20 seconds** to cycle through the 7 bugs and alternating black/white colors.
  - **Tap to Flip**: Tapping the piece immediately triggers a 360° flip animation to the next bug and resets the 20-second timer.
  - Clean, badge-free tile presentation.
- **Physical Gyroscope Parallax (`MotionManager.swift`)**:
  - Leverages `CoreMotion` (`CMMotionManager`) to read 60Hz real-time device attitude (pitch and roll).
  - Smooths raw sensor readings with an exponential moving average.
  - **Tile 3D Tilt**: Tilts the 3D piece dynamically in response to how the user holds and angles the physical device.
  - **Multi-layer Depth**: The piece shifts forward, while ambient halo glow and floating particles shift at different parallax depth layers.
  - **Dynamic Specular Sheen**: A light reflection glint glides across the hexagon face based on device angle.
  - **Realistic Shadow Projection**: Shadows project and spread in the opposite direction of the tilt.
  - **Interactive Drag Fallback**: Allows dragging with touch/finger on screen with spring-back physics.
- **Top-left button**: Dedicated **"Configurações"** button (`gearshape.fill`) opening `GameMenuSheet`.
- **Main Action Buttons**:
  1. **"Jogar contra bots"**: Vibrant hero gradient CTA button. Initiates match via 3D coin toss (`ColorDrawOverlay`).
  2. **"Online"**: Frosted glass card with `"EM BREVE"` badge (displays a gentle toast notice upon tap).
  3. **"Jogar tutorial"**: Glassmorphic CTA opening the interactive guided tutorial (`TutorialView`).

### Clean in-game board & streamlined "Configurações e Menu"
The board is completely clean of floating side buttons.
- **Top bar buttons during a match**:
  - Top-left: Invisible placeholder (settings button is exclusive to HomeView so matches are clean and distraction-free).
  - Center: Status pill ("Sua vez", "Vez do oponente", etc.).
  - Top-right: **Exit/Abandon Match** button (`xmark`) styled with a prominent
    **red accent** (`HiveTheme.danger`), asking confirmation to leave an ongoing game back to Home.
- **`GameMenuSheet`**: Opened from the top-left button on the **Home Screen**:
  - **Ações**: Pedir Dica (`lightbulb.fill`), Jogar Tutorial (`graduationcap.fill`),
    and Como Jogar (`book.fill`), all styled in standard clean white.
  - **Dificuldade do Oponente (IA)**: Prominent segmented selector (`Fácil`,
    `Médio` as default, `Difícil`) that updates difficulty dynamically.

### Interrupted Match Persistence & Clean Resume / Abandon
- When an ongoing game has started tiles and the app is closed, `GamePersistence` caches the snapshot.
- Upon reopening, `ResumeOverlay` asks if the player wants to:
  - **"Continuar Jogo"**: Restores the board state immediately and enters the game screen (`currentScreen = .game`).
  - **"Abandonar Jogo"**: Clears the saved game, resets cleanly without triggering coin flip animation (`showDrawAnimation: false`), and keeps the user on the **Home Screen** (`currentScreen = .home`).

### Drag & drop interaction (coexists with tap selection)
Players can place and move pieces either by tap-to-select → tap-target OR by
**direct drag & drop**:
- **From hand tray** (`HandTrayView`): `DragGesture(minimumDistance: 12)` lifts a
  chip towards the board. The chip source dims (`opacity 0.3`), valid drop
  targets illuminate with pulsing `TargetMarker`s on the board, and a floating
  ghost tile (`dragGhostOverlay`) tracks the finger.
- **From board** (`BoardView`): A `LongPressGesture(minimumDuration: 0.25)`
  sequenced with a `DragGesture` picks up top tiles without conflicting with the
  instant `panGesture`. The source tile dims, valid destinations highlight, and
  hovered cells glow.
- **State & Coordinate Space**: `DragState` (`@Observable`) lives on
  `GameController`. Board coordinates are converted from global finger positions
  via `globalToBoardHex` by inverting zoom, pan, and center offsets. Dropping
  onto a valid target commits the move through the existing animation
  pipeline; dropping elsewhere cancels cleanly.

### Interactive Guided Tutorial (`TutorialView.swift`)
The tutorial completely reuses the full base game engine and components:
- **Real `BoardView` & `GameController`**: Powered directly by `BoardView(game: game, onInspectPiece: { ... })`,
  ensuring 100% parity with live games.
- **Identical Drag & Drop**: Players can place and move pieces by tap-to-select OR
  by direct drag & drop with finger-following ghost tiles and target snapping.
- **Piece Travel Animations**: All moves reconstruct and animate along their complete
  `MoveGenerator.path` (step-by-step slides, grasshopper jumps, beetle climb,
  ladybug up-over-down, mosquito copying) with real-time step haptic ticks.
- **Hold to Inspect**: Long-pressing any piece on the board or in the hand tray opens
  `PieceMoveInfoOverlay` with the live animated `MovementDiagramView`.
- **Haptics & Coaching**: Valid/invalid taps receive real-time tactile feedback and
  standard coaching toast pills. Completing a drill advances smoothly to the next step.
gesture.

### Expansion roster (Mosquito + Ladybug, both sides, always on)
Both the **Mosquito and the Ladybug are permanent members of the roster** for
both colours in every match — not settings toggles.
`GameController.config(for:)` always builds the `GameState` with
`GameConfig(expansions: [.mosquito, .ladybug])`; `GameState`/`GameState.hand`
already supported an `expansions` set generically, this just always turns both
on at the app layer. Only `.pillbug` remains in the `Bug` enum without movement
rules (it would place but never move) — and it is **not** in the roster.

#### The Mosquito
- **Movement** (`Rules.mosquitoGroundDestinations`, wired into
  `MoveGenerator.destinations(forTopOf:)`): on the ground, a mosquito's moves
  are the **union** of every distinct bug type touching it, each computed as
  if the mosquito *were* that bug from its own cell (it never copies another
  mosquito). Once it has climbed onto the hive (only possible by having copied
  a Beetle to get up there), `lifted.height(hex) > 0` after lifting is the
  signal — from then on it can **only** move like a Beetle, regardless of what
  it currently touches up there.
- `MoveGenerator`'s private `destinations(forTopOf:piece:board:)` takes the
  **pre-lift** board as its `board` parameter and lifts internally into a
  local `lifted` — the height check for "is this mosquito atop the hive" must
  use `lifted.height(hex)`, not the outer `board.height(hex)` (which is always
  ≥1, since the piece itself is still on it). Getting this backwards was a
  real bug caught during development; `MosquitoTests` in
  `HiveEngineTests.swift` covers both branches.

#### The Ladybug
`Rules.ladybugDestinations(on:from:)`, wired into
`MoveGenerator.destinations(forTopOf:)`, implements the classic Ladybug move:
**exactly three steps — up onto the hive, across the top to a second tile, then
down into an empty cell** adjacent to that second tile. It always ends on the
ground (never on top) and may not return to its own starting cell. While
crossing the top it is deliberately **not** gated by the freedom-to-move rule
(it walks over tiles, it doesn't squeeze between them) — the implementation is
just the triple loop `occupiedNeighbors(start) → occupiedNeighbors(up) →
emptyNeighbors(over)`. The One-Hive cut-vertex check at the top of
`destinations(forTopOf:)` still applies before it can be lifted. A Mosquito
touching a Ladybug copies this move (`mosquitoGroundDestinations` unions it in).
`LadybugTests` covers the geometry, the generator wiring, and the mosquito copy.

### The guided tutorial
The **Play Tutorial** entry points (the board's `graduationcap.fill` camera
button and the onboarding "Play Tutorial" choice) both present `TutorialView`
(`TutorialView.swift`) — a full-screen overlay owned by `ContentView`
(`showTutorial`), **not** a game against the AI. It's isolated from the live
`GameController`: exiting just returns to whatever was on the board.
- `TutorialController` runs a scripted sequence of `TutorialStep`s built by
  `TutorialScript`. Steps include foundational mechanics (placement adjacency,
  turn-4 Queen forcing, general piece movement) followed by **dedicated
  per-bug movement drills** (Spider's exact 3-step rule, Beetle's stack climb,
  Ladybug's up-over-down path, Mosquito copying an adjacent Ant) and the final
  Grasshopper win drill.
- Each drill step loads its own small self-contained position with stable tile
  IDs. Interaction is strictly gated to the relevant action. All drill
  geometries are guarded by `TutorialScenarioTests` in the engine test suite.
- Narration is **captions only** (a coach bubble), no audio, by design.
- The board is rendered locally (its own `HexLayout` fit + `TileView`s +
  pulsing target markers), deliberately reusing `TileView`/`RegularHexagon` for
  visual parity but **not** `BoardView` (no camera/pan/zoom needed).

The last step offers **Play a Real Game** (`onPlayGame` → `game.newGame()`) or
**Done** (`onExit`). To add/reorder lessons, edit `TutorialScript.build()`; if a
move drill's piece id changes, keep the IDs in `TutorialScript` and
`TutorialScenarioTests` in sync.

### Onboarding walkthrough
First launch only (`OnboardingState.hasSeenTutorial`, a plain `UserDefaults`
bool checked in `ContentView.showOnboarding`, set the moment any of
`OnboardingOverlay`'s exit paths fire — Skip or either final-page button — so
it never reappears): a paged walkthrough (`OnboardingOverlay`, `TabView` +
`.page` style) covering the goal, turn structure, Queen/One-Hive rules, the
full tile roster (reuses `RulesView.bugs`, so add a new tile's blurb there and
both places pick it up), a strategy-tips page, and a final page with two
explicit choices instead of a generic "done" button:
- **Play Tutorial** → sets `ContentView.showTutorial = true`, launching the
  guided `TutorialView` (see "The guided tutorial").
- **Start Playing** → just dismiss, no match forced.

Vestigial: `GameOptions.tutorial` (in `GameController.swift`) and the hidden
`HiveAI.Difficulty.megaEasy` tier (depth 1, 60% blunder, filtered out of the
difficulty `Picker` by `!= .megaEasy`) date from when "Play Tutorial" started a
very weak AI match. The tutorial is now the scripted `TutorialView`, so nothing
in the UI reaches either any more — they're kept only because they're harmless
and tested. Don't wire the tutorial through them.

`TabView(.page)` overlays its page-index dots at a **fixed position** near the
bottom of the frame regardless of scroll offset — a scrollable page (tiles,
tips) whose content is taller than the frame will have its last item hidden
behind the dots on first appearance, not just off the bottom edge, because the
page opens unscrolled. Fix is a tall-enough shared `TabView` frame height (not
per-page bottom padding alone) so every page's content clears the dots without
the player needing to scroll a scroll-within-a-scroll.

### Settings / menu sheet + leaving a match
`GameMenuSheet` holds only the pre-match **setup** (opponent, difficulty,
tournament opening) now — Play Tutorial and How to Play moved out to the board's
camera controls. Rules of the flow:
- **No "Start" button.** Before the match begins, the chosen settings are applied
  to the current game when the sheet closes (`onDisappear → game.applySetup`).
- The **top-bar right button** opens setup (`slider.horizontal.3`) *only before
  play begins*. **Once play has started** (`game.hasStarted`, a tile is on the
  board) it becomes an **"X"** (`xmark`) that shows `LeaveConfirmOverlay` — a
  styled Yes/Continue modal (like `ResumeOverlay`, an in-`ZStack` overlay, **not**
  a sheet). "Yes, leave" calls `game.leaveMatch()` (ends the game, makes settings
  editable again); "Continue" just dismisses. `GameMenuSheet.startedSections`
  (Leave Match) is still reachable from the game-over "Setup" button.
- **Two sheets must never stack.** Presenting a second `.sheet` on top of the
  first throws *"only presenting a single sheet is supported"*. The menu sheet is
  hosted on the ContentView root; the **How to Play sheet is hosted on
  `BoardView`** (a different view) so the two can never both be attached to one
  view. `RulesView` carries no `NavigationStack` of its own, so whoever presents
  it (BoardView's sheet) wraps it in one and adds a Done button.

### Persistence & resume
The match is cached after **every ply** (human, AI, and auto-pass) via
`GameController.persist()` → `GamePersistence` (JSON in `UserDefaults`, key
`hive.savedGame.v1`). It's also saved when the app leaves the foreground
(`ContentView` observes `scenePhase`). The cache is **cleared** when a game ends,
on `newGame`, and on `leaveMatch`.

At launch, if a resumable match exists (ongoing, board non-empty), `init` stashes
it in `pendingResume` and **holds the AI back**; `ContentView` shows the
`ResumeOverlay` with **Continue Game** (`game.resume()`) / **Leave Game**
(`game.discardResume()`). `SavedGame` persists `options + state + history`, so
undo survives a relaunch too. `HIVE_DEMO` runs skip the resume path.

### The AI (it plays to win)
`HiveAI` is iterative-deepening **negamax + alpha-beta** with a zero-sum,
queen-surround-dominated heuristic (quadratic, so the last sides are urgent),
plus a mobility term. Design intent: the computer should *win*, not merely hinder.
Enforced by:
1. **Immediate-win first** — before anything else, any move that ends the game in
   the AI's favour is played (so it never stalls on a kill).
2. **Mate-distance scoring** — terminal scores decay with ply (`winScore - ply`),
   so it heads for the *fastest* kill instead of shuffling among equal wins.
3. **No blunder in critical positions** — the low-difficulty random-move chance is
   suppressed whenever either queen has ≥4 sides filled, so it still finishes and
   defends when it matters.

Difficulty: `megaEasy` depth 1 (60% blunder — a hidden, now-vestigial tier, see
"Onboarding walkthrough"), `easy` depth 1 (25% blunder in quiet
positions), `medium` depth 2 (no blunder), `hard` depth 4 (no blunder). Search
runs off the main actor with a time budget. **Keep `medium` at depth 2** —
`aiBeatsRandomPlayer` searches at `.medium`, and deeper makes that test slow.

### Auto-pass
If it becomes a **human's** turn and their only legal move is `.pass`
(`GameController.autoPassIfHumanStuck`), the app passes for them after a short
beat — a "no moves" position can't soft-lock the game, and the opponent can keep
pressing for the win.
